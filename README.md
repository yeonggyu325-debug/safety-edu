# 사내 안전교육 관리

Node.js 24.14 이상을 사용하는 사내 서버입니다. 별도 DB 프로그램이나 npm 패키지 설치 없이 Node.js 내장 SQLite를 사용합니다.

## 실행

프로젝트 폴더에서 다음을 실행합니다.

```powershell
npm.cmd start
```

서버 PC에서 http://127.0.0.1:3000/setup.html 을 열어 최초 관리자 이메일과 비밀번호(12자 이상)를 등록합니다. 일반 사용자는 http://서버PC의사내IP:3000 에서 로그인 없이 교육자료를 열람합니다. HTML 파일을 직접 열지 말고 서버 주소로 접속합니다.

사내망 접속을 허용하려면 서버 PC에서 다음을 실행합니다.

```powershell
npm.cmd run start:lan
```

직원들은 http://서버PC의사내IP:3000 으로 접속합니다. 최초 관리자 등록은 서버 PC의 127.0.0.1 주소에서만 가능합니다. 다른 PC에서 접속하려면 서버 PC의 Windows 방화벽에서 TCP 3000 포트를 사내 네트워크 범위에 허용해야 합니다. 서버 PC는 실행 상태를 유지해야 합니다.

## 저장 위치

기본 위치는 프로젝트의 `storage/`이며 현재 작업 폴더 기준으로 `D:\safety-edu\storage`입니다.

- `database/safety-edu.sqlite`: 사원, 부서, 근무상태 및 소속변동 이력, 관리자와 세션.
- `files/education/`: 교육자료 저장을 위한 폴더.
- `files/reports/`: 결과보고서 저장을 위한 폴더.
- `backups/`: DB·저장 파일·검증 목록을 포함한 전체 백업.

저장 경로를 바꾸려면 서버 실행 전에 `SAFETY_DATA_DIR` 환경변수를 지정합니다. `PORT`로 포트, `SAFETY_HOST`로 로컬 바인딩 주소를 지정할 수 있습니다. HTTPS 앞단을 구성한 경우 `SAFETY_SECURE_COOKIE=1`을 사용합니다.

저장 데이터는 Git에서 제외되며 웹으로 직접 다운로드할 수 없습니다.

## 현재 구현 범위

- Supabase SDK, 연결 설정과 keep-alive 작업 제거.
- 사내 HTTP 서버와 SQLite 데이터 저장.
- 교육자료 공개 열람, 관리자 전용 비밀번호 로그인·로그아웃, 30분 미사용·최대 8시간 세션.
- 부서 조회·등록·수정, 부서별 재직자 수, 소속변동 이력.
- 사원 조회·등록·수정·이메일 저장, 퇴사 처리, 퇴사자 삭제.
- 근무상태 이력과 서버 재시작 후 데이터 유지.
- 기본 교육 분류와 교육 목록의 로컬 조회·저장 기반.

PDF 업로드와 연결된 자료 미리보기를 지원합니다. Excel 자료 업로드는 구현 대상에서 제외합니다. 교육 대상자 등록·삭제, 개별·일괄 교육일과 특별교육의 두 개별 실시일 저장을 지원합니다. 사내망 운영은 현재 보류하며 출결 처리는 다음 단계입니다. 미구현 API는 성공으로 처리하지 않고 오류를 반환합니다. 일반 이용자 로그인·이메일 인증은 제공하지 않습니다. 관리자 로그인과 관리자 전용 개인 교육 이력 조회만 제공합니다.

새 설치의 초기 부서·사원 데이터는 비어 있습니다. 기존 자료는 별도 이전 도구로 가져오며, 사원명부는 관리자 CSV 일괄 업로드를 사용합니다. 운영 DB와 파일은 GitHub 업로드 대상이 아니므로 새 서버에는 별도로 백업을 복원해야 합니다.

## 파일 구조

- `index.html`, `js/`, `css/`: 기존 기능별 화면 코드.
- `js/config.js`: 사내 API 클라이언트. 기존 화면의 호출 형태를 유지하면서 원격 DB 의존성을 제거합니다.
- `server/server.cjs`: HTTP 서버, 인증 및 정적 파일 제공.
- `server/database.cjs`: SQLite 테이블, 사원·부서 API 및 데이터 검증.
- `setup.html`: 최초 관리자 설정.
- `tests/local-server.test.cjs`: 인증, 저장·조회·퇴사, 접근 제한, 재시작 후 유지 및 API 클라이언트 통합 검사.

기존 화면의 JS·CSS 로드 순서는 유지합니다.

## 검증과 백업

```powershell
npm.cmd test
npm.cmd run backup
```

백업은 `storage/backups/backup-날짜-고유번호/`에 DB 스냅샷, 교육자료·결과보고서 파일과 SHA-256 검증 목록을 함께 저장합니다. 업로드 중인 임시 파일은 제외하고, 완료 검증을 통과한 백업만 공개된 백업 폴더명으로 마무리합니다. 기존 외부 링크 주소는 DB에 보존하며 외부 서버의 실제 파일을 새로 다운로드하지 않습니다.

서버가 실행 중이면 매일 **한국 시간 새벽 3시**에 자동 백업합니다. 서버가 꺼져 있으면 자동 백업이 실행되지 않습니다. 이전 백업은 자동 삭제하지 않습니다. 같은 D 드라이브의 백업이므로 디스크 고장에 대비한 별도 디스크·사내 백업 장비 복사도 운영 정책에 맞춰 수행합니다.

검사와 복원 예시:

```powershell
npm.cmd run backup:verify -- "D:\safety-edu\storage\backups\백업폴더명"
npm.cmd run restore -- "D:\safety-edu\storage\backups\백업폴더명" --to "D:\safety-edu\storage-restored"
```

복원 대상은 **아직 존재하지 않는 새 폴더**로 지정합니다. 기존 운영 데이터를 덮어쓰지 않으며 복원한 로그인 세션은 모두 종료합니다. 복원 데이터로 전환할 때 서버를 종료한 다음 아래처럼 저장 경로를 지정해 다시 시작합니다. 검증 전 현재 저장소는 삭제하지 않습니다.

```powershell
$env:SAFETY_DATA_DIR = 'D:\safety-edu\storage-restored'
npm.cmd start
```

## 기존 교육자료 이전

`server/import-materials.cjs`는 교육 분류·목록 JSON을 가져오고 연결된 PDF·Excel 원본을 그대로 다운로드합니다. 로그인 화면이나 웹페이지를 파일로 저장하지 않도록 파일 형식을 검사합니다.

입력 폴더에는 `education_categories.json`과 `education_links.json`이 필요합니다.

```powershell
node server/import-materials.cjs 원본목록폴더
```

다운로드 파일은 SHA-256 이름으로 `storage/files/education/`에 저장하고 원래 파일명은 DB에 보관합니다. 화면 링크는 `/files/파일명`으로 연결하며 교육 목록에 연결된 파일은 로그인 없이 열람할 수 있습니다. PDF는 브라우저 열람, Excel은 다운로드로 제공합니다.

이전 전 DB 백업을 만들며 결과는 `storage/migration/import-report.json`에 기록합니다. 실패한 원본은 기존 링크를 유지하고 재실행 시 다시 시도합니다. 이미 이전한 교육 목록을 중복 생성하거나 사용자가 수정한 링크를 덮어쓰지 않습니다.

기존 교육 분류 6개와 교육 목록 43건은 로컬에 이전했습니다. 연결된 고유 자료 링크 50개는 내부 서버 기존 사내 파일 서버의 HTTP 500 오류로 다운로드하지 못했습니다. 원본 링크는 유지합니다. 이전 보안 보고서와 조사·결과 기록은 삭제했으며, 원본 목록은 storage/migration/source에 보관합니다. 파일 서버 복구 후 node --use-system-ca server/import-materials.cjs storage/migration/source 명령으로 원본 다운로드를 재시도할 수 있습니다.

## 인증·세션 정책

- 계정별 로그인 실패 3회 시 15분 잠금. 로그인 성공 시 실패 횟수 초기화.
- 실패 횟수와 잠금 시각은 SQLite에 저장되어 서버 재시작으로 해제되지 않습니다.
- 실제 사용자 조작 없이 30분이 지나면 서버에서 세션을 삭제하고 재로그인을 요구합니다.
- 자동 조회·백그라운드 폴링은 미사용 시간을 갱신하지 않습니다.
- 정상 조작은 최대 30초 간격으로 활동을 기록합니다. 계속 사용하더라도 로그인 후 8시간이 지나면 재로그인합니다.
- 일반 사용자는 `/`에서 특별·채용 교육자료와 연결된 PDF·Excel을 로그인 없이 검색·열람합니다. 정기교육 화면과 사원·개인 이력 관리는 관리자 전용입니다.
- 관리자 로그인은 상단 버튼 또는 `/login.html`에서만 진행합니다. 사원·부서·대상자 조회와 모든 자료 수정·삭제는 서버에서도 관리자 인증을 요구합니다.
- 관리자 로그아웃·세션 만료 시 공개 교육자료 화면으로 돌아갑니다. 최초 관리자 설정은 서버 PC의 `/setup.html`에서 진행합니다.
- 세션 정책 도입 시 활동 시각이 없는 기존 세션을 종료합니다. 관리자 계정과 교육 데이터는 유지합니다.
- HTTPS 및 Secure 쿠키의 운영 적용은 다음 단계입니다.

인증 정책 구현은 `server/authentication.cjs`, 브라우저 활동·만료 처리는 `js/session-policy.js`에 있습니다.

## PDF 미리보기

교육자료·결과보고서 링크 옆의 `미리보기` 버튼으로 팝업을 엽니다. 원본 링크 주소와 기존 새 창 열기는 그대로 유지하며 자료 이전·다운로드·DB 갱신은 수행하지 않습니다. PDF 직접 링크와 로컬 PDF는 브라우저 기본 PDF 뷰어를 사용합니다. Excel 링크는 기존 다운로드 방식으로 유지합니다.

확장자가 없는 파일 목록·다운로드 페이지도 저장된 주소를 그대로 표시합니다. 원본 서버의 표시 제한, 다운로드 전용 응답, 오류 또는 브라우저 설정 때문에 표시되지 않으면 `원본 링크 열기`로 확인하세요. 팝업은 닫기·Esc로 종료하며 표시 중인 프레임을 비웁니다. 외부 PDF 뷰어 서비스나 CDN은 사용하지 않습니다.

## PDF 업로드

관리자 로그인 후 교육 추가·수정 화면에서 `교육자료 PDF 업로드` 또는 `결과보고서 PDF 업로드`로 파일을 선택하고 저장합니다. 정기교육에는 두 종류를, 특별·채용 교육에는 기존 화면 구성에 맞춰 결과보고서를 연결합니다. 선택하지 않은 파일의 링크는 유지합니다. 업로드 실패 시 교육 목록의 기존 링크는 바뀌지 않습니다.

`POST /api/files/pdf`는 관리자 인증과 요청 출처를 검사합니다. PDF 확장자·헤더·종료 표식과 50MB 제한을 확인하고 원본 바이트를 `storage/files/education/`에 저장합니다. 파일명은 SHA-256으로 만들며 동일 내용은 중복 저장하지 않습니다. 원래 이름은 DB에 보관합니다. 교육 항목 저장 전 업로드 파일은 관리자만 열람하며, 교육자료에 연결하면 일반 사용자도 다운로드·미리보기 할 수 있습니다.

자료를 교체하거나 저장을 취소해도 기존 파일은 자동 삭제하지 않습니다. 백업 명령은 DB와 업로드된 PDF를 함께 포함합니다. 파일 형식 검사는 악성코드 검사나 PDF 구조 전체 검증을 대신하지 않습니다.


## 사내망 운영 설정

당분간 `npm.cmd start`와 `npm.cmd run start:local`은 로컬 PC 전용으로 실행합니다. 사내망 운영을 재개할 때 `npm.cmd run start:lan`으로 `config/intranet.local.json`과 환경변수 설정을 사용합니다. `scripts/start-intranet.cmd`를 실행해도 사내망 서버가 시작됩니다.

현재 직원 접속 주소는 **http://서버PC의사내IP:3000**입니다. 서버는 IPv4 인터페이스에서 수신하고, 실제 연결 IP가 `설정된 사내 CIDR` 또는 로컬 루프백인 경우만 요청을 받습니다. 전달 헤더로 IP 제한을 우회할 수 없으며 최초 관리자 등록은 여전히 서버 PC의 `http://127.0.0.1:3000/setup.html`에서만 가능합니다.

Windows 방화벽 설정은 **관리자 PowerShell**에서 다음을 실행합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\safety-edu\scripts\configure-intranet.ps1"
```

이 스크립트는 해당 사내 IP·TCP 포트·사내 네트워크 범위·Node 프로그램에만 인바운드 허용 규칙을 적용합니다. 네트워크가 현재 Public로 분류되어 있어도 적용되며 네트워크 분류 자체는 변경하지 않습니다. DHCP로 IP가 바뀌면 사내 담당자와 고정 IP/DHCP 예약을 정하고 설정 파일과 방화벽 규칙을 갱신해야 합니다.

다른 직원 PC에서 위 주소 접속을 확인해야 사내망 접속 검증이 완료됩니다. 방화벽이나 회사 Wi-Fi의 PC 간 통신 제한은 해당 정책 담당자가 해제해야 할 수 있습니다.

HTTPS는 회사 인증서가 준비되면 설정 파일의 `tls`를 아래처럼 지정합니다. 개인키는 채팅이나 Git에 넣지 않고 `certificates/`에 보관합니다. 인증서는 접속 도메인 또는 IP와 일치하고 직원 PC에서 신뢰할 수 있어야 합니다.

```json
"tls": {
  "cert": "certificates/server-chain.pem",
  "key": "certificates/server-key.pem"
}
```

`displayHost`를 인증서의 사내 도메인으로 바꾸면 표시 주소에도 반영됩니다. 방화벽 설정의 IP는 `listenAddress`로 별도 지정할 수 있습니다. HTTPS 실행 시 Secure 쿠키를 자동 사용하며 인증서 파일 오류 시 HTTP로 조용히 전환하지 않습니다. 현재 인증서가 제공되지 않아 HTTP로 운영합니다.

## 교육 대상자와 교육일

관리자의 교육 목록 `대상자` 버튼에서 선택 사원 또는 전체 현재 사원을 등록할 수 있습니다. 전체 등록은 퇴사자를 제외하고 이미 등록된 교육일과 비대상 사유를 보존합니다. 중복 등록하지 않습니다.

정기교육의 개별 교육일·선택 대상자 일괄 교육일, 특별교육의 개별 실시일 1·2를 로컬 DB에 저장합니다. 잘못된 날짜와 역순 날짜는 거부하며 다른 관리자의 수정과 충돌하면 최신 데이터를 다시 불러옵니다. 교육일을 입력하면 해당 사원은 대상자로 변경되고 기존 비대상 사유는 해제됩니다. 대상자 삭제와 교육일 변경에 맞춰 정기교육의 개별 기간을 서버에서도 다시 계산합니다. 자료 링크는 이 과정에서 변경하지 않습니다.

## 사원명·회사 이메일 관리

사원 추가·수정에는 사원명과 회사 이메일만 입력합니다. 부서·직급·입사일·근무상태 적용일·근무구분·비고는 입력하지 않습니다. 목록은 이름과 이메일로 검색하며 회사 이메일은 공백 제거·소문자 정규화 후 중복을 검사합니다. 같은 이름에 다른 이메일을 가진 사원은 서로 다른 사원으로 구분합니다.

`save_employee_identity`는 새 사원을 두 항목만으로 등록하고 기존 사원 수정 시 교육이력·기존 소속 정보 등을 보존합니다. `find_employee_identity`는 관리자에게만 이메일 또는 이름+이메일의 정확한 매칭 결과를 제공합니다. 새 등록의 내부 관리 번호와 기존 DB 호환용 소속 값은 서버에서 처리하며 화면 입력을 요구하지 않습니다.

전체 화면의 색상·글자 크기·간격·버튼을 `css/workspace-ui.css`로 통일했고, 사원 목록과 검색은 `js/employee-identity-ui.js`에서 담당합니다. 사내망·이메일 발송 설정은 보류한 상태입니다.


### 사원 CSV 업로드와 교육별 이력

관리자 사원 목록에서 **CSV 일괄 업로드**를 선택하고 **양식 다운로드**로 UTF-8 CSV 양식을 받을 수 있습니다. 열은 `사원명,회사 이메일` 두 개이며, 최대 1MB·5,000명까지 등록합니다. UTF-8 및 기존 한국어 CSV 인코딩을 지원합니다. 미리보기 후 **일괄 등록**을 누르면 새 사원이 등록되고 목록이 갱신됩니다.

이메일은 소문자로 정규화합니다. 기존 이름·이메일과 일치하는 사원은 건너뛰며, 파일 내 중복 이메일 또는 기존 사원과 이름·이메일 충돌이 있으면 전체 요청을 취소합니다. 기존 사원의 정보와 교육 이력은 변경하지 않습니다. 개인 교육 이력 창은 **채용시교육·특별교육**만 표시하며, 0건인 교육 탭은 숨깁니다. 정기교육은 개인 이력 총 건수와 대상자 관리에서 제외합니다. 현재 개인 이력 조회와 CSV 등록은 관리자에게만 허용됩니다.

### 사내 주소와 공개 저장소
사내 주소는 Git에서 제외되는 `config/intranet.local.json`에 보관합니다. 기존 설정값은 이 파일로 옮겼습니다. `config/intranet.json`에는 공통 기본값만 두며 허용 네트워크가 없으면 사내망 실행을 거부합니다.

환경변수는 로컬 설정보다 우선합니다. `SAFETY_HOST`는 수신 IPv4 주소, `PORT`는 포트, `SAFETY_DISPLAY_HOST`는 접속 도메인 또는 IP, `SAFETY_LISTEN_ADDRESS`는 방화벽에서 허용할 서버 IPv4 주소, `SAFETY_ALLOWED_NETWORKS`는 쉼표로 구분한 허용 사설 CIDR 목록입니다. 서버와 방화벽 스크립트는 동일한 설정 로더를 사용합니다. 방화벽 변경은 관리자 PowerShell에서 별도로 실행해야 합니다. 실행 중인 서버에 설정을 적용하려면 재시작합니다.

새 PC에서는 `config/intranet.example.json`을 `config/intranet.local.json`으로 복사하고 실제 주소와 네트워크를 지정합니다. 환경변수만으로도 설정할 수 있습니다. `.env` 파일을 자동으로 읽지는 않습니다.

웹 서버는 README, 서버 코드, 설정, 환경변수 파일, DB, 백업 및 보안 보고서 경로를 공개하지 않습니다. 교육 목록에 연결한 PDF·Excel은 기존 정책에 따라 일반 이용자에게 제공됩니다.

2026-10-07 확인 결과 연결된 GitHub 저장소는 공개이며, 기본 브랜치에는 예전 index.html과 README, keep-alive 작업이 있습니다. 공개 기본 브랜치에서 내부 IPv4 주소는 발견되지 않았지만 index.html에는 예전 Supabase URL과 JWT 형태의 키가 남아 있습니다. 로컬 코드 정리는 원격 파일이나 과거 Git 이력을 삭제하지 않습니다. 원격 변경과 키 권한·폐기는 별도로 확인해야 합니다.

## 결과보고서 등록
교육 추가·수정은 결과보고서 PDF 또는 기존 결과보고서 링크를 필수로 받습니다. 채용시·특별교육은 같은 화면에서 대상자를 1명 이상 선택해야 저장할 수 있습니다. 정기교육은 개인 대상자 등록 없이 결과보고서만 필수입니다. 교육명과 교육일도 입력합니다.

보고서와 대상자 목록은 `save_education_report` API의 한 DB 트랜잭션으로 저장합니다. 오류가 나면 교육·대상자 변경을 모두 취소하며, 다른 관리자가 교육 또는 대상자 정보를 변경했다면 다시 열어 확인하도록 안내합니다. 기존에 유지하는 대상자의 개별 교육일은 보존합니다.

새 교육자료 PDF 업로드 입력은 숨겼으며, 기존 교육자료 링크·파일·과거 교육 기록은 삭제하지 않습니다. 보고서가 없는 과거 기록은 진행중 상태로 표시하지 않고 미등록 사실만 표시합니다. 교육 목록은 분류별로 열람하며, 검색은 참석자 이름과 현재 소속 부서를 지원합니다.

일반 이용자는 상단 고정 검색바에서 이름 또는 부서를 선택하고 Enter 또는 검색 버튼으로 조회합니다. 이름은 정확히 입력하고, 부서명은 일부만 입력해도 검색됩니다. 교육명·교육일은 검색 조건으로 사용하지 않습니다. 초기화는 입력값과 검색 결과를 지우고 이름 검색으로 돌아갑니다. 관리자 세션 확인 실패와 관계없이 공개 조회를 사용할 수 있으며 관리 API 권한은 유지합니다.

## 로그인 없는 참석자·부서 검색
상단 검색바에서 이름을 정확히 입력하면 채용시·특별교육 이력을 조회합니다. 이름 앞뒤 공백은 무시하며 이메일이나 로그인을 요구하지 않습니다. 부서 검색은 현재 소속 부서명과 일치하거나 해당 문자열을 포함하는 부서 직원들의 교육을 모으며, 같은 교육은 한 번만 표시합니다. 부서 이동 전 이력도 현재 소속 부서 기준으로 조회되고 사원 이름·이메일 목록은 제공하지 않습니다.

사용자가 승인한 공개 항목은 교육 구분·교육명·공통 교육일·기존 결과보고서 링크입니다. 이메일·부서·인사 정보·사원 ID는 응답에 포함하지 않습니다. 동명이인은 사람별로 별도 표시하고, 정기교육·제외 대상자·비활성 교육은 조회 결과에서 제외합니다. 등록된 교육 대상자 기록을 사용하며 기존 DB·파일·링크를 변경하지 않습니다.

조회 전용 `POST /api/participants/search`는 공개되지만 기존 사원명부·대상자 관리·수정·삭제 API의 관리자 권한은 유지합니다.

## Supabase 참석자 일회성 동기화
`server/sync-participants.cjs`는 실행 중인 웹앱과 별개인 이전 도구입니다. 프로젝트 API가 다시 응답하며 기존 교육 43건의 원본 ID 매핑을 확인했습니다. 공개 클라이언트 키는 사원·참석자 테이블에서 권한 오류(42501)를 받으므로, 해당 프로젝트의 읽기 권한이 있는 계정 연결 또는 JSON 내보내기가 필요합니다. 2026-10-20에 인증된 연결로 원본을 내보내고 전체 백업 후 참석자 동기화를 적용했습니다. 원본·백업·실제 데이터는 로컬 storage에만 보관합니다.

JSON 내보내기 폴더에는 `employees.json`과 `education_participants.json`이 필요합니다. `education_links.json`, `education_categories.json`, `employee_departments.json`도 있으면 새 교육과 부서 연결에 사용합니다. 기존 교육은 이전 원본 ID 매핑을 우선 사용하며 기존 자료·보고서 링크는 유지합니다.

먼저 미리보기를 실행합니다. `--apply`를 붙인 실행만 기존 DB·파일 전체 백업을 검증한 후 실제로 반영합니다.

```powershell
node server/sync-participants.cjs --source "D:\\참석자원본폴더"
node server/sync-participants.cjs --source "D:\\참석자원본폴더" --apply
```

사용 가능한 프로젝트와 읽기 권한이 있다면 로컬 환경변수 `SUPABASE_URL`, `SUPABASE_KEY`를 설정한 뒤 `node server/sync-participants.cjs --remote`로 미리보고 `--apply`로 반영합니다. 키를 채팅·Git·프론트엔드에 넣지 않습니다. 원격 반영 때 수신한 원본 JSON은 Git과 웹 공개에서 제외된 storage/migration에 보존합니다.

겹치는 사원·참석자 필드는 수정 시각과 관계없이 원본 Supabase 값을 우선합니다. 명시된 null 교육일도 반영합니다. 원본에 없는 로컬 기록은 삭제하지 않습니다. 사원 매칭은 기존 매핑·이메일·사원코드, 명확한 단일 이름 순으로 확인하며 모호한 동명이인·원본 중복·잘못된 날짜·연결되지 않는 교육은 전체 반영을 취소합니다. 실제 적용도 한 DB 트랜잭션으로 처리합니다.
